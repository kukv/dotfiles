# Hunk Review（ローダー）

これは、インストール済みの `hunk` バイナリに同梱された本体の Hunk レビュースキルを
読み込むための薄いローダーである。`hunk` は mise 経由で導入しているため、同梱スキルの
パスはバージョンアップのたびに変わる。よってパスを固定せず、実行時に解決する。

## 手順

1. `hunk skill path` を実行し、同梱スキルファイルの絶対パスを取得する。
2. そのファイルの内容を読む。
3. 以下のローカルポリシーに従いつつ、その指示に沿ってユーザーの依頼を遂行する。

`hunk skill path` が失敗した場合（例: `hunk` が未インストール）は、その旨をユーザーに伝え、
mise での導入（`mise install`）を促して停止する。

## ローカルポリシー

これらのルールは同梱スキルの上に重なり、この構成では優先される。前提は herdr の分割ペイン
構成で、片方があなた（コーディングエージェント）、もう片方が Hunk。複数の worktree タブや
ワークスペースを同時に開くため、**他タブ・他ワークスペースの Hunk を絶対に奪わない**ことが
最優先の制約になる。正確なコマンド構文は同梱スキルに委ね、以下はペインとセッションの
選択方針だけを縛る。

### 1. ペインとセッションの用意

**同梱スキルの「Hunk を自分で起動するな」という指示は、この構成では適用しない。**
代わりに、レビューを見せる前にこのスクリプトを実行する:

```bash
~/.claude/skills/hunk-review/ensure-hunk-pane.sh
```

呼び出し元のペインの右隣に、この worktree の Hunk を冪等に用意して JSON を返す:

```json
{"pane":"wA:p4","pane_action":"split-reused","hunk_action":"hunk-alive","session":"6d60cf85-..."}
```

- `hunk_action` が `hunk-alive` なら既存の Hunk をそのまま使う（起動し直さない）
- `hunk_action` が `blocked`（終了コード 2）なら、右ペインが nvim などで使用中。
  **何も起動せず**、`busy_with` の中身をユーザーに伝えて指示を仰ぐ
- 終了コード 1 は herdr の外にいるか Hunk が起動できなかった場合。ユーザーに伝えて停止する

### 2. セッション選択（複数セッションでの安全性）

以降の `hunk session` コマンドは、**すべて上で得た `session` の ID を位置引数で渡す**。

- `--repo` を使わない。同一 repo root のセッションが別タブにも存在しうるため一意にならない
- セレクタ無しの auto-resolve に頼らない
- スクリプトはペインの前面プロセス pid と `hunk session list --json` の `.sessions[].pid` を
  突き合わせて特定している。プロセス名で判定してはいけない（npm ラッパーが native hunk を
  子として起動するため、起動直後は名前が入れ替わる）

### 3. 依頼に応じた変更の表示

得た `<session-id>` で、同梱スキルの `reload` コマンドによりライブセッションを再読み込みする:

- 作業ツリーの変更: `-- diff` で reload
- 特定のコミットや範囲: `-- show <ref>` / `-- diff <range>` で reload

その後、最初に注目すべきハンクへ navigate する。
